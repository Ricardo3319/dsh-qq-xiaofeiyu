QQ × DSH：开源组件接入清单

核对日期：2026-11-06。共 50 个可访问的候选仓库，覆盖联网、知识问答、长期记忆、拟人互动、QQ 生态、语音表情和订阅。维护日期、星数、归档状态和许可来自 GitHub API 当日快照；接入建议是结合本仓库代码作出的判断。

保留 NapCat → dsh-qq-bridge → DSH 主链。机器可读清单 · 既有 DSH 插件目录 · 既有记忆与风格调研

第一项：联网与知识问答

qq_web_search 调用本地 SearXNG，最多返回五条去重结果及来源；qq_read_url 调用 Jina Reader 读取公开网页，每次默认最多 6000 字，可按返回的 next_start 继续读。资料进入当前对话，模型据此回答；这一步不是持久化文档知识库。

工具只在总开关开启、非试运行且允许联网时请求服务。网页只作为资料，并附有忽略网页指令、引用来源的说明。阅读默认使用 Jina 公共服务，用户提供的网址会发给该服务；不上传整段会话。设置入口：DSH → 通到 QQ → 消息 → 联网搜索与链接阅读。

接口依据：SearXNG Search API、Reader 使用说明。Jina 阅读实测可用；搜索接口实测 HTTP 401，因此搜索采用 SearXNG。

体验迭代：长文续读与追问（已实现）

现在可以继续问“后半段讲了什么”。阅读工具返回 next_start，模型将它传入 start 即可续读；末尾返回 null。每个 QQ 会话独立缓存最近八页公开正文，有效期为抓取完成后十分钟；连续追问复用同一份内容。重启后缓存清空，不写入长期记忆。

需要最新状态时使用 refresh: true，会同时跳过本地缓存与 Reader 的缓存。工具标明本地获取时间 fetched_at、是否命中缓存和正文长度。长文跨越缓存有效期或主动刷新后可能变化，应从头重新阅读；该时间不是网页发布日期。

体验迭代：共同记忆查看、纠正与删除（已实现）

在 QQ 里说“列出你在这里记住的事”，模型可用 list_common 查看当前聊天的有效记录，每页十条，支持涉及的人和类别筛选。每条有固定编号，可继续说“把编号 12 改成……”或“忘掉编号 12”；编号以查询结果为准，不是列表顺序。

update_common 只纠正指定内容和可选类别，保留原事件日期；forget_common 精确删除一条。修改和删除都限当前群或当前私聊；旧的片段删除及 remember_common 的取代仅唯一命中时执行。来源不明、匹配歧义或保存失败会明确返回失败，总开关关闭或试运行时不执行写操作。

沿用本地存储，无新增依赖。旧记录首次通过工具访问时补充持久编号，删除后不复用编号。这里只管理共同记忆，不包含群友簿、鱼的记忆或完整聊天历史；本次接入前本机没有共同记忆文件，初次列表为空属于正常结果，未创建虚构示例记忆。

体验迭代：群聊按需摘要（2026-11-07 已实现）

在当前群 @ 它说“总结最近一小时的讨论”或“哪些事定了，哪些还没定”。qq_group_digest 提供带发言人和时间的缓存记录，由当前对话模型整理讨论、明确结论、待办/未决，避免把提议当成定案。默认回看 60 分钟，可指定 1–1440 分钟；不接受其他群号，也不允许在私聊查询。

复用正常轮询已取得的消息，包含未点名的群内讨论和机器人已发的消息，不会因此额外唤醒模型。每群最多保留最近一天的 500 条、每条 1000 字符；每页最多 80 条、正文合计 12000 字符。next_before_id 可用于继续读取较早记录；工具同时提供实际时间范围、截断条数和最近成功拉取时间。

无新增依赖或模型服务。缓存只在内存中，重启清空；停用群绑定、关闭总开关或进入试运行后，下一次轮询清理缓存。摘要查询不新增历史请求，不自动发日报，也不写共同记忆。

体验迭代：免打扰与主动互动节奏（2026-11-07 已实现）

按聊天保存免打扰起止、时区、平时最小间隔、工作日最小间隔。本机选定北京时间 Asia/Shanghai 的 01:00–08:00 安静，平时至少 20 分钟、周一至周五至少 60 分钟。跨午夜可用，含起不含止；起止相同关闭安静时段，间隔取平时和工作日较大值。

未点名群聊插话在入站处略过，不开模型回合，也不会到点补发；自动回复在推往 QQ 前按目标聊天把关。私聊来信、@、引用和叫名字按原回复流程处理，同一会话绑定多个聊天时，仅实际触发的聊天获得放行。成功主动发出后才记录冷却时间，部分成功也计时；该时间随原有水位保存，重启后继续生效。

入口为“通到 QQ → 绑定 → 免打扰与主动互动”。qq_interaction_settings 可在聊天中查询、修改当前聊天的有限设置；群内修改接受主人（首个私聊绑定），私聊仅当前对象可改。无参数只查看，非法时间/时区不落盘，关闭或试运行时不执行工具修改。沿用现有主动搭话插件和消息链，不新增依赖。

体验迭代：聊天偏好（2026-11-07 已实现）

qq_chat_preferences 保存当前聊天的私聊称呼、回复长短和语音偏好。可说“以后叫我阿云”“回答短一点”“先别发语音”；网页绑定页也能调整或恢复默认。群内整体设置仅主人可改，私聊仅当前对象可改。无参数只查询，试运行或关闭时不执行工具修改。

称呼与长短挂在独立系统提示段，多个聊天共享会话时不混用；语音关闭由发送端执行，覆盖语音工具、唱歌与随机主动语音，并在合成完后再次读取设置。原有身份、人设、语音识别不变。两组新增测试已通过；真实 QQ 对话尚未验证。

另存 16 种性格候选（JSON）：含对比示例、可复制模板和五个官方参考链接，全部仅收藏未启用。中文模板为项目原创整理，不是下载的上游角色卡，也不自动导入当前人设。

体验迭代：聊天文件问答（2026-11-07 已实现）

发送 PDF、TXT、Markdown、CSV、DOCX 或 XLSX 后，在当前聊天问“总结这份文件，标出出处”。qq_read_document 无参数列文件，指定返回的 document_id 读取；长内容按 next_page 和 next_start 续读。群文件遵从原有点名规则，不自动读取或总结每个上传文件；私聊纯文件不再静默丢弃。

复用 NapCat 文件接口（参数核对其 源码示例）和本机已有 Poppler 的 pdfinfo / pdftotext，未安装第二套文档框架。PDF 返回实际文件页码，文本返回行号；临时 PDF 解析完删除，不发给 Reader 服务，提取正文交给当前对话模型回答。

DOCX/XLSX 使用 Python 3 标准库读取 ZIP/XML，未安装 Office 框架。依据微软的 Word 正文结构和 Excel 单元格结构实现；Word 引用段落/表格行，Excel 引用工作表/单元格，分段编号不是 Office 页码。公式只读缓存且标明可能过期，无缓存时不计算；数字不应用格式，日期可能是序列数，隐藏表及行列也会读取。

每聊天保留最近一小时最多十份文件记录和提取缓存，重启或停用后清空。工具不接受任意路径、网址或跨聊天编号。最大 10MB，PDF 最多前 100 页，Excel 最多前 20 张表和 2 万个非空单元格，Word 最多 2 万个非空段落/表格行，Office XML 解压后累计上限 16MB；正文总计 20 万字符，每次至多 6000 字符，截断明确标记。不做 OCR，不读取 DOC/XLS、宏格式、图片图表、嵌套转发附件或 Word 页眉页脚/批注/脚注/文本框，不还原复杂布局。消息直链失效且有 file_id 时只重新获取链接下载一次。Office、链接恢复、原有 PDF/文本解析测试通过；真实 QQ 文件对话尚未验证。

体验迭代：工具与提示挂载清理（2026-11-07）

门槛、空间和其他 QQ 工具均跟踪实际会话实例，实例替换后重新挂载；多个绑定共享同一会话只注册一份。停用最后一个绑定或卸载插件会撤销工具，热重载不会残留旧注册。人设和偏好提示的并发装配复用待完成任务，卸载立即撤销，异步完成后不会重新出现。两组生命周期测试通过；未修改人设内容，16 份候选仍仅收藏。

额外体验修复：重启恢复会话（2026-11-07 已实现）

已启用且未归档的 QQ 绑定由 DSH 会话控制器恢复原会话，失败每分钟再试；关闭或试运行时不恢复。绑定状态按实际 agent 显示，会话替换后重新挂工具。本机已确认四个绑定恢复成功、聊天偏好工具全部挂载；原有两份人设与仓库模板对账一致。

后续按真实使用反馈扩展

当前五项体验迭代已有可用实现。下一轮优先看真实 QQ 文件、语音或回复失败样本，再决定是否需要 Office/OCR、复杂表格解析、语义检索或换语音模型；MarkItDown、Docling 等仍保留为候选。没有创建定时开发任务，也没有自动启用收藏的性格。

第二项：主动回忆与拟人对话

recall_common 让模型按人名、事情或关键词主动查询已保存的共同记忆，返回类型、日期、来源和内容；支持筛选事件、事实、约定。无命中返回空结果，排除已取代和已过期条目，私聊检索限当前对象，群记忆沿用原有跨群共享规则。

参考 qq-agent-plus 的显式回忆工具思路，以及 rank_bm25 的词频和长度排序。BM25 使用本地独立实现的正 IDF 变体，并结合现有时间衰减；没有安装这些项目，也没有把它们的代码复制进桥。原来的自动摘要、群友簿、心情、主动搭话插件继续工作。

按依赖顺序推进

  1. 已实现：搜索、链接阅读、带来源的回答。
  2. 已实现：显式记忆检索与日期/作用域信息。
  3. 文件问答已接入 Poppler 和 DOCX/XLSX 基本文字提取；扫描件、复杂表格或排版还原有实际需求时，再比较 MarkItDown / Docling。
  4. 有回忆失败样本后：比较现有 BM25 与语义检索，再决定是否引入 Mem0、MemOS 或向量库。
  5. 有互动样本后：参考 MaiBot 的发言判断，调整现有 dsh-speak-up/门槛；不并行启动第二条 QQ 消息处理链。

本地部署

源码和 Python 环境在项目忽略目录 .runtime/，与机器人原有依赖隔离。安装使用 uv；无需 Docker。下列命令在仓库根目录运行：

git clone --depth 1 https://github.com/searxng/searxng.git .runtime/searxng
uv venv .runtime/qq-search --python 3.12
uv pip install --python .runtime/qq-search/bin/python -r .runtime/searxng/requirements.txt granian
# 首次部署生成本地配置；已有配置时跳过，命令不会覆盖现有文件
python3 - <<'PY'
from pathlib import Path
import secrets
template = Path('deploy/searxng-settings.yml.template').read_text()
config = Path('deploy/searxng-settings.yml')
with config.open('x', encoding='utf-8') as output:
    config.chmod(0o600)
    output.write(template.replace('REPLACE_WITH_RANDOM_SECRET', secrets.token_hex(32)))
PY
# 将 deploy/qq-search.service.template 中 <REPO> 换成仓库绝对路径，
# 保存到 ~/.config/systemd/user/qq-search.service
# 本机 DSH 已通过 EnvironmentFile 配置 Clash 代理；另将
# deploy/dsh-web-network.conf 安装为
# ~/.config/systemd/user/dsh-web.service.d/60-qq-web-network.conf
systemctl --user daemon-reload
systemctl --user start qq-search.service
systemctl --user restart dsh-web.service
# 通到 QQ 的搜索地址：http://127.0.0.1:8888
# 通到 QQ 的阅读地址：https://r.jina.ai

服务仅监听回环地址。实际配置为 deploy/searxng-settings.yml，含本机随机密钥，已加入 Git 忽略规则；仓库只保存 deploy/searxng-settings.yml.template。服务是否开机启动与现有机器人一样由用户决定，不自动 enable。更换 Reader 时只改阅读服务地址。停止搜索：systemctl --user stop qq-search.service。start-all.sh 已把搜索纳入整套启停、状态和自启管理。
