# 门槛判「不接」之后，下一轮真正想说的话会被静默吞掉

> **已发**：<https://github.com/Yuuyuko-uu/dsh-qq-bridge/pull/27>（2026-10-31，基于 `main` @ 1.4.3）。
> 这份留作记录 —— 复现步骤、根因和补丁都在下面。
>
> 版本：1.4.3 里仍然存在；1.1.2 也一样。

## 现象

群里开了「回复门槛」+「门槛真停轮」之后：**每判一次「不接」，紧接着的下一句真正想说的话发不出去**，
而且日志里**一条记录都没有** —— 看起来就像「它回了，但群里没出现」。

## 复现

1. 群绑定上打开 `门槛` 和 `门槛真停轮`。
2. 群里有人说了句跟它无关的话 → 模型调 `qq_reply_gate` 传 `reply=false` → 这一轮被 cancel 成 `aborted`。
3. 紧接着有人 @ 它 → 模型正常写了一句回复，`turn/end` 是 `completed`。
4. **这句回复不会发出去。** 日志里没有任何 `⚠`、没有「跳过」，什么都没有。

## 实测证据

同一间会话连着两次，两发两中：

```
15:39:22  turn 347  qq_reply_gate{reply:false}  → turn/end aborted
15:41:05  turn 348  「<一句本来该发出去的回复>」+ 一张图 → turn/end completed  ← 没发出去

15:43:49  turn 349  qq_reply_gate{reply:false}  → turn/end aborted
15:44:07  turn 350  「<另一句本来该发出去的回复>」+ 一张图 → completed  ← 也没发出去
```

同期旁边没被判「不接」的那几轮（344→345→346、351→352→353）全部准时发出，所以不是发消息那一侧的问题。

## 根因

`lib/host.js` 的 `收到事件()`，`turn/end` 分支（1.4.2 的 1246 行附近）：

```js
if (完成 && 上一轮.轮号 === d.turn && 有东西 && !已发轮.has(轮标)) {
  ...
  if (静默轮.has(键)) {
    静默轮.delete(键)          // ← 只有 完成 === true 才走得到
    记账('回复门槛：这一轮按判定跳过发送（' + 短id(键) + '）')
  } else {
    void 落地一发(...)
  }
}
```

门槛判「不接」是靠 `agent.cancel()` 停那一轮的，所以它的 `turn/end` 是 **`aborted`**：
`完成 === false` → 整个 `if` 块跳过 → **`静默轮` 里那个标记没被清掉**。

下一轮完成时进到同一个 `if`，`静默轮.has(键)` 为真 → 它把这轮当成「判定过的不接」直接跳发送，
再顺手把标记清掉。也就是说：**标记永远只推迟一轮生效，吃掉的是下一句话。**

## 建议的修法

标记本来就该只对「触发它的那一轮」有效。所以除了在发送分支里消费，**任何一轮结束时都要收尾**：

```diff
         if (静默轮.has(键)) {
           静默轮.delete(键)
           记账('回复门槛：这一轮按判定跳过发送（' + 短id(键) + '）')
         } else {
           void 落地一发(配置, 上一轮.文本, 上一轮.图们, 方向, 是QQ唤醒)
         }
+      } else if (静默轮.has(键)) {
+        // 这一轮没走到「要不要发」那一步（被门槛 cancel 成 aborted，或者压根没说话）——
+        // 标记也必须在这里清掉，不能留到下一轮。
+        静默轮.delete(键)
+        记账('回复门槛：静默标记在这轮结束（' + 短id(键) + '），不带进下一轮')
       }
       记上一轮(空轮())
```

再补一处兜底（万一某轮根本没发 `turn/end`，比如宿主被杀）：

```diff
     const 记上一轮 = (v) => 上一轮们.set(键, v)

+    // 新一轮一开，上一轮的静默标记就必须作废。
+    if (event && event.type === 'turn/start') {
+      静默轮.delete(键)
+      return
+    }
+
     if (event && event.type === 'assistant/message') {
```
